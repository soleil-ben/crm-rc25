# Physical label validation — human test protocol

> ## ⚠ NOT VALIDATED
>
> **No label has ever been printed, and no barcode has ever been scanned.** Every field
> below is blank and must be filled in by the person who physically printed and scanned a
> label. Claude cannot execute any part of this and must not fill in any field.
>
> If no printer is available, mark the gate **blocked by missing hardware**. Blocked is not
> passed. **Do not change the PDF design to obtain a result** — altering geometry to make a
> test pass is how an unscannable label reaches a loading dock.

**Owner decision:** OD-18 — open. The acceptance hardware has not been named.

---

## Field classes on this sheet

Four kinds of field appear below, and they must never be confused with one another.

| Class | What it is | State before review |
|---|---|---|
| **Content under review** | The screen, sentence, template or check being judged. Written in advance as part of this sheet | Prewritten — **not** a reviewer's answer |
| **Reviewer response** | What the reviewer judged, observed or would change | **Blank** |
| **Evidence obtained** | What the reviewer actually captured — recordings, transcripts, screenshots, photographs | **Blank** |
| **Result / sign-off** | The outcome, the signature and the date | **Blank** |

Prewritten content is never evidence that this sheet was reviewed. A sheet is reviewed
only when the **Reviewer response**, **Evidence obtained** and **Result / sign-off**
fields have been filled in by the person who did the work.

## 1. Hardware and settings

Record exactly what was used. A pass on one printer is not a pass on another.

| Field | Reviewer response |
|---|---|
| Printer make and model | |
| Driver and version | |
| Operating system and version | |
| Print path (direct / driver / PDF reader) | |
| Media size (e.g. 4×6 in / 100×150 mm) | |
| Media type (direct thermal / thermal transfer) | |
| **Resolution — 203 or 300 dpi** | |
| Print scaling (must be **100% / actual size**) | |
| Darkness setting | |
| Speed setting | |
| Label stock supplier and part number | |

> **Why dpi matters.** DEC-0034 sets the Code 128 module width at two printer dots **at
> 203 dpi**. At 300 dpi the same geometry produces a narrower bar. If the printer is
> 300 dpi, record it and expect the scan result to be the thing that decides, not the
> design note.

> **Why scaling matters.** Any "fit to page" or "shrink to fit" invalidates the whole
> test. DEC-0035 says an identifier is never shrunk to fit; a driver that scales the page
> defeats that silently.

## 4. Multiple consecutive labels

A single label proves the geometry. A run proves the feed.

| Check | Expected | Reviewer response | Result |
|---|---|---|---|
| Print a multi-package shipment as one job | Every package gets its own label | | |

| Gap / registration | Each label starts at the top of its stock | | |

> The system records that a label **document was generated**, not that a printer produced
> anything (CRM.md section 8). Nothing in the application can confirm a physical print —
> which is exactly why this protocol exists.
